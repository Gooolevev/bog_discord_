# AGENTS.md — discord-bot

Discord-бот для Minecraft-сообщества: Python 3.11+, discord.py 2.x, asyncio.
Slash-команды, Pollinations AI, статус MC-сервера и автопостройка Discord-сервера.

## Структура и запуск

- `__main__.py` — короткая точка входа; `main.py` — запуск, список `COGS` и синхронизация команд.
- `bot/cogs/general.py` — развлекательные и информационные команды.
- `bot/cogs/minecraft.py` — `/server`, запросы через mcstatus.
- `bot/cogs/ai.py` — `/ai` и ответы на упоминания.
- `bot/cogs/builder.py` — `/построй`, `/ресет`, роли и структура сервера.
- `bot/cogs/monitor.py` — фоновый мониторинг MC-сервера.
- `bot/cogs/community.py` — постоянные интерактивные опросы и сбор команды.
- `bot/utils/ai.py` — промпты, ответы-заготовки и запросы к Pollinations.
- `bot/utils/resources.py` — учёт созданных объектов в `data/builder.sqlite3` для безопасного сброса.
- `bot/utils/community.py` — карточки и ответы в `data/community.sqlite3`.
- `bot/utils/settings.py` — настройки серверов в таблице `guild_settings` той же базы.
- `bot/dashboard.py` — закрытый локальный API панели, жизненным циклом управляет `DiscordBot`.
- `website/` — официальный сайт «Контур» и панель управления на Next.js.
- Настройки в `.env`: см. `.env.example`; для AI нужен `POLLINATIONS_API_KEY`.
- Запуск: `./venv/bin/python __main__.py`.

## Разработка

- Сначала изучи связанные файлы. Исправляй причину проблемы минимальным изменением.
- Если задача понятна, реализуй её без лишних вопросов. Не трогай посторонние ошибки.
- Не добавляй зависимости, абстракции и файлы без необходимости.
- Команды: `@app_commands.command` внутри Cog, параметры — `@app_commands.describe`.
- Каждый ког регистрируется через `async def setup(bot)` и `await bot.add_cog(...)`;
  новый модуль добавляй в `COGS` в `main.py`.
- Для долгих команд используй `defer()` и `followup`; приватные ошибки — ephemeral.
- Проверяй права административных команд, аргументы и ограничения длины сообщений Discord.

## Асинхронность и API

- Не блокируй event loop: асинхронный HTTP, `asyncio.sleep()`, закрытие сессий при завершении.
- Управляй жизненным циклом фоновых задач и корректно обрабатывай `asyncio.CancelledError`.
- Задавай таймауты, учитывай rate limits, проверяй HTTP-статусы и содержимое ответов.
- Повторы — ограниченные, с задержкой; ошибки авторизации и некорректные данные не повторяй.
- Для AI обрабатывай пустые ответы и ограничения провайдера; отделяй ввод пользователя
  от системных инструкций, не раскрывай внутренние промпты через команды.
- Используй `logging`, не скрывай ошибки пустыми `except`. Пользователю — понятное сообщение,
  в журнал — контекст без секретов и приватных запросов.

## Безопасность и файлы

- Секреты — только в `.env` или окружении; не добавляй их в код, тесты, логи и Git.
- Не перезаписывай `.env`, не изменяй `venv`, не добавляй временные файлы и кэш в проект.
- Не выполняй пользовательский ввод как Python-код или shell-команды; проверяй файловые пути.
- Перед удалением файла проверь его использование. Пользовательские данные и конфигурации
  не удаляй без разрешения.
- Без запроса пользователя не делай commit, push, удаление веток или переписывание истории Git.

## Проверки и отчёт

- После изменения Python проверь синтаксис, импорты и регистрацию затронутых когов.
- Запусти `./venv/bin/ruff check .`; изменения логики проверь тестами, включая ошибки и границы.
- Тесты: `./venv/bin/python -B -m unittest discover -s tests -v`.
- Не заявляй об успешных проверках, которые не запускал; укажи причину пропуска или сбоя.
- Отвечай кратко, на русском: что изменено, какие файлы затронуты, что проверено и что осталось.
- Об обнаруженных проблемах безопасности сообщай обязательно.

## Официальный сайт и панель управления

- Бот сохраняет существующие команды и архитектуру. Сайт находится отдельно в `website/`.
- Стек сайта: Next.js App Router, React, TypeScript, Tailwind CSS, shadcn/ui, next-themes,
  `next/font`. Стабильные совместимые версии закреплены в `website/package-lock.json`.
- По умолчанию используй серверные компоненты; клиентские — для демонстрации, темы и форм.
- Дизайн — главный приоритет: выразительная типографика, графитовая и светлая темы,
  синие/бирюзовые акценты, продуманные отступы, доступность и мобильная адаптация.
  Не добавляй вымышленные отзывы, статистику и возможности. Демонстрации помечай явно.
- Учитывай `prefers-reduced-motion`; не запускай музыку автоматически. Spotify — официальный
  Embed, ссылка задаётся конфигурацией; отсутствие настройки не маскируй демонстрационным треком.
- Discord OAuth2 работает на сервере Next.js. Сессии — в защищённых HttpOnly cookies;
  секреты и OAuth-токены не передавай клиентским компонентам и не сохраняй в Git.
- Интеграция: Next.js server → закрытый aiohttp API работающего бота на loopback.
  API выключен без настройки; отдельный секрет обязателен. Бот проверяет актуальные права
  пользователя и наличие бота на сервере при каждом защищённом запросе.
- Настройки сервера хранятся отдельной таблицей в существующей `data/community.sqlite3`.
  Значения `.env` сохраняются как совместимые настройки по умолчанию; `.env` не перезаписывай.
- Первая панель: включение мониторинга Minecraft, канал уведомлений, длительность опросов.
  Все настройки должны реально применяться; никаких фиктивных сохранений и статусов.
- Публичная главная работает без Discord-секретов; отсутствие OAuth/API объясняется понятным
  состоянием интерфейса. Не добавляй обход авторизации и демонстрационные аккаунты в панель.
- Запуск сайта: `cd website && npm install && npm run dev`. Проверки:
  `npm run lint`, `npm run typecheck`, `npm test`, `npm run build`.
- После интеграции повторно выполняй Ruff и Python unittest. Реальный OAuth и Discord
  проверяются только с настроенными секретами; непроведённые проверки отмечай в отчёте.
- Сейчас работа локальная: без публикации, Docker, внешней базы, commit и push.
- Перед большими изменениями кратко объясняй намерение и жди «делай»; текущая разработка
  сайта и панели уже разрешена пользователем. Для следующих крупных этапов учитывай контекст.
