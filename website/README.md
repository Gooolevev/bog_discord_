# Discord Bot — сайт Discord-бота

Next.js App Router, React, TypeScript, Tailwind CSS, shadcn/ui и next-themes.
Сайт работает отдельно от Python-процесса, но изменяет его реальные настройки через закрытый API.
Новые Python-зависимости не нужны.

## Посмотреть сайт

Требуется Node.js 20.9+ (проект проверен с Node 26) и npm.

```bash
cd website
npm ci
npm run dev
```

Открой **http://127.0.0.1:3000**. Главная, демонстрация и Spotify работают без Discord-секретов.
Панель без конфигурации покажет понятное сообщение. Автоматического входа или фиктивных аккаунтов нет.
Сайт никуда не опубликован.

В музыкальном разделе можно вставить ссылку на плейлист, альбом или трек Spotify.
При настроенном SPOTIFY_URL официальный плеер виден сразу; без настройки — после ввода ссылки. При готовности плеера сайт однократно вызывает play() официального Spotify iFrame API. Браузер может заблокировать автозапуск со звуком; тогда нужно нажать Play в плеере. Полные треки доступны согласно ограничениям Spotify.
Чтобы заранее заполнить ссылку, задай `SPOTIFY_URL` в конфигурации. Ссылка публичная — секретов в ней быть не должно.

## Подключить настоящий Discord-вход

1. Скопируй `website/.env.example` в **новый** файл `website/.env.local`, если его ещё нет.
2. Открой [Discord Developer Portal](https://discord.com/developers/applications) и выбери
   **то же приложение, которому принадлежит существующий бот**.
3. В General Information скопируй Application ID в `DISCORD_CLIENT_ID`.
4. В OAuth2 скопируй Client Secret в `DISCORD_CLIENT_SECRET`.
5. Добавь в OAuth2 → Redirects ровно этот адрес:
   `http://127.0.0.1:3000/api/auth/callback`.
6. Создай **два разных** случайных секрета длиной от 32 символов: `SESSION_SECRET` и `BOT_API_SECRET`.
   Для генерации каждого можно выполнить `openssl rand -hex 32` локально. Не отправляй значения в чат и не добавляй их в Git.
7. В существующий корневой `.env` вручную добавь:

   ```dotenv
   BOT_API_PORT=8081
   BOT_API_SECRET=тот_же_секрет_что_в_website_env_local
   ```

8. В `website/.env.local` проверь `BOT_API_URL=http://127.0.0.1:8081` и совпадение `BOT_API_SECRET`.
9. Запусти бота обычной командой из корня проекта и перезапусти сайт:

   ```bash
   ./venv/bin/python __main__.py
   ```

Используй один и тот же адрес **127.0.0.1**, а не вперемешку с localhost: иначе не совпадут OAuth cookie и адрес возврата.
Секрет OAuth2 — не токен бота. `DISCORD_TOKEN` остаётся только в корневом `.env` Python-приложения.
Никаких реальных секретов в примерах нет; существующий `.env` автоматически не меняется.
Для будущего размещения потребуется HTTPS и согласованные `SITE_URL` / Redirect URI.

## Что работает в панели

После входа список пересекается с серверами установленного бота. Требуется владелец, Administrator
или Manage Guild. Права проверяются заново и сайтом, и ботом при каждом защищённом запросе.

- **Наблюдать за Minecraft** — включает/выключает мониторинг для выбранного Discord-сервера.
- **Канал уведомлений** — только текстовые каналы этого сервера, доступные боту для сообщений и Embed.
- **Время на общий выбор** — стандартная длительность новых `/poll`, включая форму из `/hello`.
  Параметр конкретного опроса имеет приоритет. Уже опубликованные опросы не меняются.

Настройки сохраняются сразу. Мониторинг учитывает их в следующем цикле (до минуты).
Адрес самого Minecraft-сервера остаётся существующим `MC_SERVER` из `.env`; сайт не позволяет
произвольно направлять сетевые запросы Python на чужие адреса.
Существующий `MONITOR_CHANNEL` используется как совместимая настройка по умолчанию,
пока для его Discord-сервера не сохранены настройки через панель.

## Архитектура и безопасность

```text
Браузер → Next.js server routes → 127.0.0.1:8081 / aiohttp → работающий бот
                                                     → data/community.sqlite3
```

- `app/` — страницы, OAuth callback и серверные API-маршруты.
- `components/` — демонстрация, формы и адаптированные компоненты shadcn/ui.
- `lib/auth.ts` — непрозрачные сессии в памяти, не более часа и 1000 записей.
- `lib/bot-api.ts` — проверка прав Discord и запросы к закрытому Python API.
- `../bot/dashboard.py` — внутренний API с отдельным секретом; слушает только loopback.
- `../bot/utils/settings.py` — таблица `guild_settings` в **существующей** базе сообщества.

Браузер получает только случайный ID HttpOnly-сессии, не OAuth-токен. Cookie — SameSite=Lax,
в production также Secure. OAuth state подписан и ограничен 10 минутами.
Сохранение и выход проверяют Origin; защищённые ответы не кэшируются.
После перезапуска сайта сессии исчезают — для первой локальной версии это намеренное упрощение.
Несколько процессов Next.js с общими сессиями пока не поддерживаются.

Manrope хранится локально с лицензией OFL и подключён через `next/font/local`.
Аналитики и внешних запросов за шрифтами нет. Анимации учитывают `prefers-reduced-motion`.

## Проверки

```bash
cd website
npm run lint
npm run typecheck
npm test
npm run build
# При запущенном npm run dev (или npm start в другом терминале):
npm run test:http
```

Из корня:

```bash
./venv/bin/ruff check .
./venv/bin/python -B -m unittest discover -s tests -v
```

Автотесты не используют настоящий Discord-токен. Проверяются OAuth state, Origin,
права, валидация настроек, безопасные Spotify-ссылки, закрытые API, сохранение и применение настроек.
Полный OAuth-вход, приглашение в Discord и реальное проигрывание Spotify требуют внешних сервисов;
их успешность нельзя считать подтверждённой одними unit-тестами.

Production-проверка локально: `npm run build`, затем `npm start`. Для реальной авторизации
в production требуется HTTPS; для локальной работы с OAuth используй `npm run dev`.
