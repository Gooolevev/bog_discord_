## Архитектура

### Discord.py

- Используй API discord.py 2.x.
- Все команды оформляй через `app_commands`.
- Команды размещай в соответствующих Cog.
- Не размещай бизнес-логику непосредственно внутри обработчиков команд, если она может быть переиспользована.
- Для долгих операций используй `defer()` и корректное завершение interaction.
- Учитывай ограничения Discord API и rate limits.
- Проверяй права пользователя перед выполнением административных операций.
- Не доверяй переданным пользователем ID и аргументам без проверки.
- Используй ephemeral-ответы для приватных ошибок и административных операций, когда это уместно.

### Async Python

- Не блокируй event loop.
- Не используй `time.sleep()` в асинхронном коде.
- Для задержек используй `asyncio.sleep()`.
- Для HTTP-запросов используй асинхронные клиенты.
- Не создавай бесконтрольные фоновые задачи.
- Корректно обрабатывай отмену задач (`asyncio.CancelledError`).
- Не используй синхронные тяжёлые операции внутри async-функций.
- Закрывай HTTP-сессии и другие ресурсы при завершении приложения.
- Избегай глобального изменяемого состояния.

### HTTP и внешние API

- Устанавливай разумные таймауты.
- Обрабатывай сетевые ошибки.
- Обрабатывай HTTP-коды ответов.
- Учитывай rate limits.
- Не выполняй бесконечные циклы повторных запросов.
- Используй ограниченные retry с задержкой и exponential backoff, если это уместно.
- Не повторяй запросы бездумно при ошибках авторизации или некорректных данных.
- Проверяй формат и содержимое ответов API.

### AI-интеграция

- Не отправляй API-запросы без необходимости.
- Учитывай ограничения провайдера.
- Обрабатывай ошибки, таймауты и пустые ответы.
- Не допускай бесконечных повторных запросов.
- Не блокируй Discord event loop.
- Сохраняй ограничения частоты запросов.
- Не раскрывай SYSTEM_PROMPT, токены и внутренние настройки через пользовательские команды.
- Не позволяй пользовательскому вводу бесконтрольно изменять системные инструкции.
- Ограничивай длину входных и выходных сообщений Discord.

## Безопасность

Это обязательные требования.

- Никогда не хардкодь токены, пароли и API-ключи.
- Все секреты должны находиться в `.env` или переменных окружения.
- `.env` не должен попадать в Git.
- Не выводи секреты в логи.
- Не добавляй реальные токены в тесты и примеры.
- Проверяй права доступа перед административными действиями.
- Не выполняй пользовательский ввод через `eval()` или `exec()`.
- Не запускай shell-команды из пользовательского ввода.
- Не удаляй и не перезаписывай пользовательские данные без необходимости.
- При работе с файлами проверяй пути и предотвращай path traversal.

## О проекте
Discord-бот на Python (`discord.py` v2, async) для майнкрафт-сообщества: slash-команды, дерзкая нейронка (Pollinations, бесплатно), статус MC-сервера, автопостройка сервера.

## Структура
- `__main__.py` — точка входа: создание `commands.Bot`, список `COGS`, загрузка когов, синхронизация slash-команд в `on_ready`, ретраи подключения (сеть режет gateway).
- `bot/cogs/` — коги (модули команд):
  - `general.py` — /ping /hello /roll /coin /choose
  - `minecraft.py` — /server (mcstatus)
  - `ai.py` — /ai + listener `on_message` (упоминания → нейронка, пустой пинг → «Пошёл нахуй»)
  - `builder.py` — /построй (только админы): роли/категории/каналы из dataclass-конфигов
- `bot/utils/ai.py` — SYSTEM_PROMPT, SHORT_PERSONA, ROAST_COMEBACKS, `ask_pollinations` (лимит 1 ответ/45с на IP, парсинг «wait N seconds» из 402), `ask_ai` (отказ → роаст).

## Конвенции
- Код и комментарии — на русском.
- Команды — `@app_commands.command` внутри когов; описания параметров — `@app_commands.describe` (кириллица допустима).
- Каждый ког: класс `commands.Cog` + `async def setup(bot): await bot.add_cog(...)`.
- Новый ког добавлять в список `COGS` в `__main__.py`.
- Токены только из `.env` (`DISCORD_TOKEN`, `MC_SERVER`).
